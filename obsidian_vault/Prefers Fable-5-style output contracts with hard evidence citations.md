# Prefers Fable-5-style output contracts with hard evidence citations

## What it is

For technical/documentation deliverables, the user wants hard output contracts: mandatory file:line citations, explicit [INFERRED]/[NOT-IN-SOURCE] tags on anything not directly sourced, confidence columns, a silent self-check pass before returning, and domain-appropriate vocabulary (e.g. RDK/Android/Linux-TV terms for Vantiva work).

## Why it matters

Without these contracts, generated documentation reads as authoritative when parts of it are actually inferred, which is the opposite of what a codebase-documentation deliverable is for.
