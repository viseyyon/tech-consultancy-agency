# Expects verification, not assumption, before calling anything done

## What it is

The user wants real evidence behind any "done" claim: parse checks, strict typechecks, interop test suites, page-by-page document verification, rather than a description of what should work. Honest limits and residual gaps must be stated explicitly rather than smoothed over.

## Why it matters

Declaring work complete on assumption rather than verification is exactly the failure mode that produced repeated false-pass incidents across this user's projects.
